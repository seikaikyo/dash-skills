# 同步與閘門：補齊差異解析、二進位檔、釘版腳本與中斷時的退回

- **type**: fix
- **建立日期**: 2026-11-16
- **status**: in-progress

## 背景

2026-11-16 的安全審查在每日同步流程另外確認四個低風險問題，接在 `sync-gate-fail-closed-2026-11-16` 之後修：

1. 閘門從 `git diff` 文字逐行判斷哪些是新增內容，判斷方式只看行首字元。上游內容本身的某些行形狀會讓閘門把新增內容歸到別的檔案或整段漏看；檔名需要跳脫時，路徑解析也會錯，連帶讓印出的放行指令雜湊欄變空。這些檔案若剛好在掃描器的舊告警基準裡，兩層檢查都不會擋。
2. 掃描器把二進位檔與壓縮檔列為「不在檢查範圍」，`scan-split.py` 判斷完整度時不看這份清單，閘門就把這類檔案當成已檢查過。其中有壓縮檔會被解壓進使用者的專案。
3. `pin-refs.py` 走訪 `external/` 時會跟著上游放的符號連結讀寫 repo 以外的檔案。
4. 同步是直接寫進已載入的 `external/`。閘門跑完前流程若被中斷，沒檢查過的內容會一直留在載入位置，直到下次同步。

## 變更內容

1. `scripts/gate-external.py`
   - `added_lines()` 改成依區塊狀態解析：檔頭只在區塊外讀，區塊內每一行 `+` 都算新增內容；以位元組讀取，只用換行字元切行；git 輸出加 `core.quotePath=false` 與固定前綴。
   - 檔名仍無法解析的檔頭當成擋下理由（規則 `diff-parse`），放行清單對它沒有作用。
2. `scripts/scan-split.py`
   - 掃描報告裡「不在檢查範圍」的檔案也要在 `security-reports/scan-incomplete-allow.tsv` 有對應的一行（含雜湊）才算完整；內容一變就失效。
   - 拆分掃描合併報告時保留這份清單並補上子目錄前綴。
   - `--accept` 一併接受這類檔案。
3. `scripts/pin-refs.py`：略過符號連結與非一般檔案，實際路徑不在走訪根目錄內的也略過。
4. `scripts/auto-update.sh`：同步開始後設定結束時的處理，閘門沒有正常完成就把 `external/` 退回 HEAD（涵蓋中斷與提早結束）。

不在這次範圍：把同步改成先寫到未載入的暫存目錄、過閘門後才搬進 `external/`。這是結構調整，另開提案。

## 影響範圍

- 只動閘門、掃描輔助、釘版與排程腳本。
- 上線後，帶二進位檔的集合第一次有變更時，若接受清單沒有這些檔案的雜湊就會被隔離。上線時先用 `--accept` 把目前已提交版本的雜湊登記進本機接受清單（canvas-design、theme-factory、web-artifacts-builder）。
- 接受清單只在本機，不進 repo。

## 測試計畫

1. 新增測試，改動前的腳本要失敗、改動後要通過：
   - 新增內容裡有以 `++` 開頭的行，後面接會被擋的內容：閘門擋下。
   - 新增內容含歸位字元（CR）切開的行：閘門照樣看到會被擋的內容。
   - 檔名含非 ASCII 字元的新檔案含會被擋的內容：閘門擋下，放行指令的雜湊欄不是空的。
   - 報告的 `scope_exclusions` 有檔案而接受清單沒有：判定不完整；加上雜湊相符的一行後判定完整；檔案內容改變後再判定不完整。
   - 拆分掃描的合併報告保留 `scope_exclusions` 並補上子目錄前綴。
   - `pin-refs.py`：指到 repo 外檔案的連結，外部檔案內容不變。
   - `auto-update.sh`：閘門執行中被中斷，`external/` 退回 HEAD。
2. 既有的三套測試全過。
3. `bash -n` 與 Python 語法檢查通過。
