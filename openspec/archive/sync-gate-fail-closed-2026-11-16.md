# 同步與閘門：失敗時一律退回、複製不跟隨連結、放行指令加跳脫

- **type**: fix
- **建立日期**: 2026-11-16
- **status**: completed

## 背景

2026-11-16 對每日同步流程做了一次安全審查，確認三個中風險問題：

1. 閘門執行中拋出例外時，有變更的集合不會退回上一版。`auto-update.sh` 把閘門的輸出接到 `sed`，看不到閘門的結束碼，之後照常重建連結、提交並推送。上游檔案裡出現無法以 UTF-8 解碼的位元組，就足以讓閘門在退回前中止。
2. `update-external.sh` 在整包 `cp -RP` 之後，又用不帶 `-P` 的 `cp` 複製 README、LICENSE 等固定檔名。上游若在這些位置放符號連結，這一步會跟著連結讀寫 repo 以外的檔案，而且發生在閘門之前。
3. 閘門與 `scan-split.py` 在隔離後印出一行可直接貼上的放行指令，裡面的路徑來自上游檔名，只用單引號包住沒有跳脫。檔名帶單引號時，貼上那行就會執行檔名裡的其他內容。

## 變更內容

1. `scripts/gate-external.py`
   - 呼叫 git 的輸出解碼改成遇到無效位元組就替換，不拋例外。
   - `quarantine()` 的退回動作移到 `finally`，複製隔離副本或寫紀錄失敗也會退回。
   - 每個集合的檢查包在例外處理裡：出錯就退回該集合、記錄原因、繼續檢查下一個；只要有任何一個出錯，結束碼非 0。
   - 放行指令的每個欄位都用單引號包住並跳脫內含的單引號；路徑或原因含控制字元時不印放行指令。
2. `scripts/scan-split.py`：「看過後接受」的指令用同樣方式跳脫。
3. `scripts/auto-update.sh`：取閘門本身的結束碼（`PIPESTATUS`）。非 0 時把 `external/` 退回 HEAD，跳過連結重建、提交與推送，以非 0 結束。
4. `scripts/update-external.sh`
   - 新增兩個輔助函式：複製來源目錄前確認路徑上每一層都不是符號連結；複製固定檔名時來源必須是一般檔案，目的地先刪除再以 `cp -P` 複製。
   - 所有同步函式改用這兩個輔助函式。
   - 需要用 `sed -i` 改寫的 `SKILL.md` 不是一般檔案時，該集合同步失敗，保留上一版。
   - 移除 agent-browser 的 `EXTENSIONS.md` 保留與還原：目前沒有這個檔案，留著只會多一個跟隨連結寫入的位置。
5. `scripts/tests/`：新增對應測試。`test_sync_script_never_follows_symlinks` 原本只檢查帶旗標的 `cp`，沒帶旗標的 `cp` 看不到；改成所有 `cp` 都要帶 `-P`（`-RP` 或 `-P`），檢查範圍變大，沒有放寬。

## 影響範圍

- 只動同步、閘門與掃描輔助腳本，不動 `external/` 內容。
- 正常的同步結果不變。閘門出錯的那一天不會提交，隔天重跑。
- 放行指令對一般檔名的輸出與改動前相同。

## UI規格

無畫面變更。

## 測試計畫

1. 新增測試，改動前的腳本要失敗、改動後要通過：
   - 已提交的文字檔被改成含無效 UTF-8 位元組並加入會被擋的內容：閘門不拋例外，該集合退回 HEAD。
   - 單一集合檢查出錯時：該集合退回，其他集合照常檢查，結束碼非 0。
   - 檔名含單引號的檔案被隔離：印出的放行指令交給 shell 執行後不會執行其他指令，放行清單寫進正確的四欄。
   - 檔名含控制字元：不印放行指令。
   - `scan-split.py` 的接受指令同樣跳脫。
   - 同步輔助函式：來源路徑中有一層是符號連結時拒絕；固定檔名的來源是符號連結時不複製；目的地已是符號連結時先刪除，不寫到連結目標。
   - `auto-update.sh` 取用閘門結束碼，非 0 時退回並停止提交。
2. `python3 scripts/tests/test_gate.py` 與 `python3 scripts/tests/test_gate_structure.py` 全過。
3. `bash -n` 與 `py_compile` 通過。

## 結果

- 新增 12 個測試，其中 10 個在改動前的腳本上失敗，改動後全過；另 2 個是確認一般情況輸出不變的對照組。
- 加強後的 `test_sync_script_never_follows_symlinks` 在改動前的腳本上失敗，改動後通過。
- 三套測試共 60 個全過，`bash -n` 與 Python 語法檢查通過。
