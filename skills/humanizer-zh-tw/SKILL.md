# humanizer-zh-tw

把一段已經寫好的正體中文改寫得更像真人寫的，保留原意與資訊，拿掉讓人一眼看出是 AI 生成的痕跡。

## 什麼時候用

使用者手上有一段既有文字，要你讓它讀起來更自然、更像人話，或是直接說「這段很 AI」「幫我潤一下」「去 AI 味」。對象是正體中文（台灣用語）。英文文字走 humanizer-en。

這是改寫工具，不是檢查器。破折號、emoji、裝飾符號這類符號層問題由既有 hook 攔，不在這裡逐條檢查。這裡處理的是人讀得出來、但工具抓不到的東西：填充語、公式化的句型、死板的節奏、過度客套的語氣。

## 改寫流程

1. 讀完整段，抓住它真正要講的事。
2. 找出 AI 痕跡（見下面兩張黑名單與自檢清單）。
3. 改寫：保留原意與所有事實，換掉填充語，打斷公式化結構，讓長短句交錯。
4. 回傳改好的文字。若使用者需要，再附一兩句說明動了哪些地方。

不改原意、不加原文沒有的內容、不動引用區塊與程式碼。文字裡的數字、人名、專有名稱照原樣保留。

## 禁止的詞彙

改寫時把這些換成直白的說法：

| 類型 | 要換掉的用語 |
|------|------|
| 連接詞 | 此外、與……保持一致、然而，以及各種收尾套語 |
| 誇大詞 | 至關重要、關鍵性的、深入探討、充滿活力 |
| 模糊歸因 | 專家認為、業界報告顯示、觀察者指出 |
| 宣傳語 | 開創性的、令人讚嘆的、必遊之地、致力於 |
| 空洞結尾 | 問候、徵詢後續、祝福這類沒有資訊的客套話 |
| Hedge 字 | 建議考慮、似乎這類判斷性 hedge 拿掉（語氣詞的可能、或許、應該，口語 OK） |

連接詞與空洞結尾還有一份固定的強制清單由 hook 擋，那份是底線，本表處理的是清單以外、更細的語感。

支語換回台灣用語：崗位改職位、培訓改訓練、對齊改講清楚、數據改資料、配置改設定、項目改專案、響應改回應、導入改匯入。

## 禁止的結構

| 模式 | 問題 | 改法 |
|------|------|------|
| 三段式 | 「創新、靈感與洞察」這種剛好三項的排比 | 改兩項，或四項以上，或直接描述 |
| 否定式排比 | 「不僅……而且……」 | 直接陳述 |
| 淺層分析句 | 「象徵著……」「確保了……」這種填充式收尾 | 刪掉或改成具體的話 |
| 繫詞迴避 | 「作為一個……」「充當……」 | 直接用「是」 |
| 空洞結尾 | 段落用一句漂亮但沒資訊的話收 | 收在最後一件實際的事上 |

## 講話的基準

技術或工作內容的改寫，往這個方向靠：

- 先講事情本身，配具體數字，不要先鋪陳做了什麼。
- 術語換成日常說法，必要時給對照。
- 分項講，每項先講做了什麼再講為什麼，一項不超過三四句。
- 數字要具體到可以驗證，不要「大幅」「顯著」。
- 短句，不要一句話塞三個轉折。
- 結尾不加自我表態，不加「還有什麼需要」。

判準：對方不用回頭問「這是什麼意思」就算改到位。

## 快速自檢

改完回頭看一遍：

- 連續三句長度一樣？打斷一句。
- 段落收在一句漂亮的空話上？換個收法。
- 出現「此外」「然而」？多半直接刪掉就通順。
- 三項列舉像套版？改成兩項或四項以上。
- 讀起來像維基百科或新聞稿？補一個具體的點或觀點。

## 輸出格式

預設只回傳改好的文字，讓使用者可以直接用。使用者若問動了哪些地方，再用一兩句條列說明主要的改動，不要長篇解釋。
