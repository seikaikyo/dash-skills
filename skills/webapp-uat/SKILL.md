# webapp-uat

對已部署的 web app 做一輪使用者驗收。目標不是「頁面有打開」，是「一個真的使用者走過去不會卡住、不會看到錯誤、三種語言都對、手機到桌機都不壞」。

## 工具：agent-browser 為主

驗證、截圖、E2E、三尺寸 RWD 一律用 agent-browser CLI，直接用不需請示。只有要看 production（含 seikai.dev）登入後的頁面才換 chrome MCP，而且要先 `claude --chrome` 啟動加當次口頭授權，缺一就退回 agent-browser，且只做單頁讀取不批次刷頁（大量請求會觸發 Vercel BotID 封 IP）。場景對照見 browser-tools.md。

一個 agent-browser session 一次下一個指令，不要並行打同一個 session，否則它會重啟跳到 about:blank。

## 一輪 UAT 的流程

### 1. 盤點畫面
先列出要走的畫面：主流程頁、子頁、表單、空狀態、錯誤路徑。不要只測首頁。

### 2. 逐畫面走
每個畫面做這幾件事：

- 打開，等載入完成，截圖留證。
- 讀 console：有沒有 error 或 warning。production 不該出現 `console.error`（ErrorBoundary 與 main 入口例外），也不該有 `console.log`。
- 讀 network：有沒有 4xx / 5xx 的請求，有沒有打到預期外的網域。自家 API 掛掉要回 503 而不是假資料。
- 操作主要互動：按鈕、表單送出、導航。看有沒有回饋、會不會卡住。

### 3. 三尺寸 RWD
每個主要畫面在三個尺寸各截一張，檢查有沒有破版、有沒有橫向捲動、文字會不會被切：

- 手機 375x812
- 平板 768x1024
- 桌機 1280x720

### 4. 三語 i18n
介面是 zh-TW / en / ja 三語。切過每一種語言，檢查：

- 有沒有漏翻、露出 key 名或預設語言。
- 切語言後版面會不會因為字長不同而破。
- 日期、數字格式有沒有跟著語言走。

### 5. 無障礙
- 鍵盤能不能走完主流程，focus 樣式看不看得見。
- 圖片有沒有 alt，`<nav>` 有沒有 aria-label。
- 對比夠不夠（文字對背景）。
- 標題階層有沒有亂跳。

### 6. 部署後對照 Sentry
是剛部署的站就查 Sentry（org dashai-jz）最近有沒有新的未解決 error。頁面上看起來正常不代表伺服器端沒丟錯。

## 問題分級

找到的問題照這個分，讓使用者一眼看出要先修哪個：

- Blocker：主流程走不下去，或 production 出現 5xx、未處理例外、資安問題。立刻修不累積。
- High：功能可用但有明顯錯誤，console error、破版、漏翻、鍵盤走不了。
- Medium：體驗瑕疵，對比不足、空狀態沒引導、次要互動無回饋。
- Low：文案、間距、對齊這類細節。

每個問題寫清楚：哪個畫面、哪個尺寸或語言、重現步驟、預期與實際、嚴重度。不要只說「怪怪的」。

## 輸出

一輪跑完給一份報告：走了哪些畫面、各尺寸與語言的結果、照嚴重度排序的問題清單（含位置與重現步驟）、截圖路徑。沒問題的畫面也列出來，讓使用者知道涵蓋範圍，不是只報壞的。
